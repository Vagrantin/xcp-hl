## How to record a real decision

For this Phase 1 packet, #201 requires two humans for each exact page/locale: one technical reviewer and one language reviewer. No people are assigned here. Ask them to link an explicit decision that names the page, locale, source commit and hashes.

Only after that approval, update the existing record under `reviews[translationKey][locale]` in `site/data/xoa_manual_reviews.json`. Required fields:

| Field | Required value |
| --- | --- |
| sourceRevision | Exact source hash from the approved row above |
| translationRevision | Exact translated hash from the approved row above |
| technicalReviewer | Actual human technical reviewer identity |
| languageReviewer | Actual human language reviewer identity |
| reviewedAt | Actual approval date, YYYY-MM-DD |
| reviewUrl | Actual GitHub decision URL covering this exact page and locale |

Set that page to `translationStatus: reviewed` only after the decision is recorded. Preserve unrelated old records. A later meaning or glossary change requires a new packet and decision.

Run from the repository root:

```bash
python3 -I site/scripts/check_xoa_manual.py --report /tmp/xoa-review-queue.json
python3 -I site/scripts/check_xoa_manual.py --require-reviewed --report /tmp/xoa-reviewed-gate.json
python3 -I site/scripts/check_translation_parity.py
```

The first and third checks pass for this source. The strict reviewed gate intentionally fails on these 18 drafts. The production workflow must retain `XOA_PUBLICATION_MODE=reviewed`. Obtain fresh exact-head CI results and the remaining cutover evidence before any merge or publication.
