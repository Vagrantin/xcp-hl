**XOA-HL アプライアンス**の既存の管理者セッション、使い捨て VM、新しいテストユーザー用の別ブラウザーセッションを用意します。練習中は管理者セッションを使える状態に保ちます。最後の管理者のアカウントや自分の権限をテスト中に変更しないでください。

## 1. アカウントとオブジェクトの役割を区別する

**設定 → ユーザー一覧** (`/#/settings/users`) はアカウント全体の権限を設定します。**User** は一般アカウントです。**Admin** はオブジェクトの ACL 確認を迂回する管理者です。特定のオブジェクトへの **Admin** 付与は別の概念で、そのオブジェクトと権限の適用範囲に対して働きます。

| オブジェクトの ACL 役割 | 許可する操作 |
| --- | --- |
| Viewer | 閲覧 |
| Operator | 閲覧と操作 |
| Admin | 閲覧、操作、管理 |

最初はテスト VM 1 台に **Viewer** を付与します。ホストやプールへの付与では、VM 1 台より広いオブジェクトへのアクセスを許可する場合があります。グループに付与した権限はすべての所属ユーザーに適用されます。権限は加算されます。1 つの ACL を削除しても、別のグループ、オブジェクト、親から許可されたアクセスは残ります。この検証では拒否ルールを使いません。

## 2. 一般のテストユーザーを作成する

**設定 → ユーザー一覧** で、メールアドレスまたはログイン名と固有のパスワードを持つ別のテストユーザーを作成します。全体の **Admin** ではなく **User** を選びます。表示された権限を確認します。本番の資格情報を使ったり、証跡にパスワードを記録したりしないでください。

別のブラウザーセッションでテストユーザーとしてログインし、ACL 追加前に見える範囲を記録します。管理者のログインを再利用しておらず、正しいテストユーザーであることを確認します。元の管理者セッションを開いたままにし、権限の修正や取り消しに使えるようにします。

## 3. VM 1 台に Viewer を付与する

管理者として **設定 → ACL一覧** (`/#/settings/acls`) を開きます。対象ユーザーはテストユーザーだけ、対象オブジェクトは使い捨て VM だけ、役割は **Viewer** を選んでルールを追加します。追加された行のユーザー、オブジェクト、役割を確認します。この練習では全オブジェクトやプール全体を選びません。

フォームで複数のユーザーとオブジェクトを指定すると、それぞれの組み合わせにルールを作成します。オブジェクトやタグのフィルターは現在の対象を選ぶ補助です。この練習は将来作成される対象へのポリシーを設定しません。似た表示名だけで判断せず、識別情報を確認してください。

## 4. 表示と制限された操作を確認する

一般ユーザーの画面を更新するか、再ログインします。対象 VM が表示され、基本情報を読めることを確認します。起動、停止、管理操作が使えないことも確認します。操作を要求できる場合は、VM を変更せずに拒否される必要があります。拒否のテストは使い捨て VM だけで行います。ボタンが隠れているだけではサーバー側の認可を十分に検証できません。

想定外に操作が成功したら練習を中止します。管理者としてアカウント全体の権限、グループ所属、VM、ホスト、プールへの他の権限を確認します。原因不明のアクセスエラーを解消するために権限を広げないでください。配布版で ACL 画面がない場合はバージョンとエラーを記録して[報告](/docs/xoa-hl/troubleshooting/)します。他の製品版の有料プランが必要だと判断しないでください。

## 5. 取り消して再確認する

管理者として正確なテスト用 ACL を削除します。テストユーザーの画面を更新するか再ログインし、VM へのアクセスがなくなったことを確認します。残る場合は他の直接付与、グループ、継承の権限を調べます。1 行の削除はすべての権限の取り消しではありません。残した管理者が引き続きログインして対象を管理できることも確認します。

資格情報を含めず、アカウント種別、権限の範囲、期待した結果と実際の結果を記録します。下のローカルグループの練習ではこのテストユーザーを保持し、すべての練習が終わってから削除します。この検証では、すべての委任操作、リソースセット、外部認証、バックアップジョブの委任、API トークンの範囲は確認しません。広い変更を行う前に[ホストとプールの管理](/docs/xoa-hl/hosts-pools/)と[設定エクスポート](/docs/xoa-hl/configuration-backup/)を参照します。

[ワンタイムコード (OTP) でローカルアカウントのサインインを保護する](/docs/xoa-hl/sign-in-otp/).

## 6. ローカルグループでアクセスを付与する {#group-access}

新しいローカルグループ、セクション 2 の一般テストユーザー、同じ使い捨て VM を使います。先にセクション 5 を完了し、直接付与したテスト ACL を削除してください。他のグループや親オブジェクトからの VM アクセスもないことを確認します。比較用に、グループに所属しない 2 つ目の一般アカウントを用意し、管理者セッションも保持します。グループのオブジェクト ACL は所属ユーザーに適用されますが、ユーザーを追加してもアカウント全体の権限は変わりません。

1. **設定 → グループ一覧** (`/#/settings/groups`) を開きます。**New Group Name** に `lab-vm-viewers` などの固有名を入力し、**Create** を選びます。新しいグループにユーザーがいないことを確認します。名前が既にある場合は、内容や権限の分からないグループを再利用せず、別の名前にします。この版では、グループ一覧のこれらのラベルは英語です。
2. **設定 → ACL一覧** で、このグループだけを対象者、テスト VM だけを対象オブジェクト、**Viewer** を役割に選びます。ルールを作成して、グループ・VM・役割の行を確認します。空のグループではテストユーザーにアクセスは付与されません。両方の一般アカウントで最初の表示範囲が変わらないことを確認します。
3. **グループ一覧** に戻り、対象グループの **Add User** 列で目的のユーザーだけを選びます。選択すると所属の変更がすぐに送信され、別の保存ボタンはありません。**Users** 列の人数をプラスアイコンで展開し、ログイン名を確認します。**設定 → ユーザー一覧** でも所属グループの数・詳細を調べ、このグループが含まれることと、全体の権限が **User** のままであることを確認します。エラーが出たら両方の画面を更新してください。所属の 2 つのレコードは別々に書き込まれるため、片方の一覧だけが正しく見えても十分ではありません。
4. 所属ユーザーの画面を更新するか再ログインします。VM の情報を読める一方、起動・停止・管理操作は利用できないか、使い捨て VM を変更せずに拒否されることを確認します。比較用アカウントには引き続きその権限がないことも確認します。結果が異なる場合は停止し、本人の識別情報、全体の権限、所属グループ、すべての直接・継承 ACL を調べます。テストを成功させるために広い権限を追加しないでください。
5. **グループ一覧** のメンバー一覧を展開し、正確なテストユーザーのログイン名の横の削除アイコンを使います。確認ダイアログなしで、削除要求がすぐに送信されます。グループからログイン名が消え、ユーザーの詳細からそのグループが消えたことを確認します。元のメンバーの画面を更新・再ログインして、このグループによる VM アクセスがなくなったことを確認します。グループの ACL は残るため、他のメンバーがいればその権限も残ります。

権限が加算されることを確認するには、ユーザーをもう一度グループに追加し、Viewer アクセスが戻ったことを確認します。同じ VM に対して、そのユーザーへの直接の **Viewer** ACL を別途追加してから、グループの VM ACL だけを削除します。ユーザーは直接の ACL によって引き続き VM を読めるはずです。その直接の ACL も削除してアクセスを再確認します。他の付与がなければ、グループに所属していても VM アクセスはなくなるはずです。グループルールがないことは拒否ルールではなく、全体の管理者はオブジェクト ACL の確認を迂回します。

片付けでは、対象者が存在する間にテスト ACL を削除し、テスト用の所属を解除して、両方の一般アカウントの結果を確認します。その後、空のローカルテストグループの行と名前を再確認し、その行の **Delete Group** を選んで削除を承認します。確認ダイアログは一般的な内容なので、開く前にグループを識別してください。グループ・ACL・ユーザーの画面を更新し、独立した管理者を保持します。グループの削除後、ACL と所属の片付けは非同期に行われます。グループが消えても、関連するすべてのレコードの処理が終わったとは限りません。ACL 一覧は対象者が存在しなくなった行を非表示にする場合があります。要求が失敗したり記録が一致しなかったりする場合は停止し、秘密情報を除いた識別情報・エラーを記録して、再試行や追加の削除の前に[不整合を報告](/docs/xoa-hl/troubleshooting/)してください。

認証プロバイダーで同期したグループは、この演習の対象外です。ローカルの名前・所属の操作は制限されます。制限を回避するために **Synchronize LDAP groups** を実行したり、認証プロバイダーとの関連を解除したりしないでください。入れ子グループ、名前変更、リソースセット、クォータ、ディレクトリ同期、すべての委任操作は個別の検証が必要です。
