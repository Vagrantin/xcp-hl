小さな検証用 VM を作成して OS をインストールし、仮想ディスクから起動できることを確認します。

{{< callout type="info" >}}
プレビュー用の手順です。XO 5.113.2（`e281c536`）とイメージ `xoa-image-20261009-5f33c81` の XOA-HL パッチでソースを確認しました。検証環境での一連の操作とゲスト OS ごとのテストは未実施です。以下のリソース量は例であり、対応ゲスト OS の一覧ではありません。この翻訳はレビュー待ちです。
{{< /callout >}}

## 始める前に

- [ログインしてホストを接続します](/docs/xoa-hl/first-login/)。このガイドでは XOA-HL 管理者アカウントを使います。
- OS の提供元からインストール ISO をダウンロードし、提供元が公開したチェックサムで検証します。
- インストールメディア用の **ISO SR** と、VM ディスク用の空き容量がある **書き込み可能な SR** を確認します。両者の用途は異なります。[XCP-HL ISO ライブラリの利用条件](/docs/features/#iso-storage)を確認してください。すべてのホストに存在するわけではありません。
- インストーラーに必要な接続を提供するゲストネットワークを選びます。XOA-HL と既存の VM のための容量を残し、ホストの RAM とストレージの空きを確認します。

管理操作は **ブラウザー** で行います。OS のインストールは **新しく作成したゲスト VM のコンソール** で行い、XCP-HL ホストや XOA-HL アプライアンスには実行しません。

## 1. インストール ISO を取り込む

1. XOA-HL で **インポート → Disk**（`/#/import/disk`）を開きます。ダウンロード済みのファイルをアップロードするため、**From URL** はオフのままにします。
2. **ISO SR** を選びます。存在する場合は `XCP-HL ISO library` が例です。アップロード領域に `.iso` ファイルをドロップします。
3. ファイル名と保存先を確認し、**インポート** を選んで完了を待ちます。
4. 保存先 SR のディスク一覧に ISO が表示されることを確認します。アップロードが未完了の状態で先へ進まないでください。

適切な ISO SR が表示されない場合は、先に ISO リポジトリを用意します。通常の VM ディスク用ストレージにメディアを取り込んでも、ISO ライブラリにはなりません。

## 2. VM 作成ウィザードに入力する

**新規作成 → 仮想マシン(VM)**（`/#/vms/new`）を開き、目的の **プール** を選びます。OS がインストール済みのテンプレートではなく、ゲスト OS に適したインストール用テンプレートを選んでください。

`lab-first-vm` など、識別しやすい名前を使います。次の例は、OS 提供元の要件を満たす場合に限り、小さな Linux の検証環境に使えます。

| ウィザードの項目 | 選択内容と目的 |
| --- | --- |
| 仮想マシン(VM)情報 | インストール用テンプレート、名前、説明を選びます。 |
| スペック | 例：2 vCPU、2 GiB RAM。インストーラーがより多く必要とする場合は増やします。 |
| インストール設定 | **ISO/DVD** と取り込んだ ISO を選びます。 |
| ネットワークインタフェイス | ゲストネットワークを選びます。ネットワーク設計上の指定がなければ、MAC アドレスは空欄にして自動生成します。 |
| 仮想ディスク | 例：目的のホストから利用できる書き込み可能な SR に 20 GiB のディスクを 1 本作成します。システムディスクに ISO SR を選ばないでください。 |
| 詳細設定 | ゲストに必要な変更が文書化されていなければ、テンプレートの既定値を使います。最初の起動を手動で行うため、**Boot VM after creation** のチェックを外します。 |
| 概要 | VM を 1 台作成する前に、プール、テンプレート、CPU、RAM、ネットワーク、保存先を確認します。 |

**VMの作成** を選びます。**確認：** 選んだ名前の VM が 1 台表示され、設定が入力内容と一致します。ボタンが無効の場合は、必須項目またはリソースの確認が未完了です。再試行する前にウィザードを見直してください。

## 3. OS をインストールする

1. 新しい VM を開いて名前を確認し、起動します。**コンソール** タブを開きます。
2. 選んだインストーラーが起動することを確認し、このゲスト内で OS 提供元の手順に従います。
3. インストール先ディスクを選ぶ際は、**新しい VM の仮想ディスク** であることを確認します。この例では 20 GiB のディスクを作成しています。想定外の既存データがある場合は停止し、選択中の VM を確認してください。
4. インストール後、VM の **Disks** タブで仮想 CD ドライブから ISO を取り出します。ゲストを通常の手順で再起動し、仮想ディスクから起動することを確認します。

{{< callout type="warning" >}}
操作対象は新しい検証用 VM だけです。ディスクの初期化や強制停止ではデータが失われる場合があります。ゲストが応答する場合は通常のシャットダウンや再起動を使い、このゲストの再起動のために XOA-HL アプライアンスやハイパーバイザーを停止しないでください。
{{< /callout >}}

## 4. 結果を確認する

- インストール ISO なしでゲストが起動し、コンソールからログインできます。
- VM の CPU、メモリー、ディスク、ネットワークが選択内容と一致します。
- ゲスト内で IP アドレス、ゲートウェイ、DNS、必要な通信を確認します。ゲストのネットワークが使えない場合も、コンソールから確認できます。
- ゲスト OS のバージョン、テンプレート、VM 名、インストール済み XOA-HL のバージョンを記録します。ゲストツールとその導入手順は OS に依存します。このチュートリアルは、検証済みのゲストツール導入手順を提供するものではありません。

この VM にはまだ独立したバックアップがありません。同じストレージ上のスナップショットでは、そのストレージの喪失に対応できません。バックアップと復元を検証するまでは、重要なデータを保存しないでください。

## うまくいかない場合

| 症状 | 確認と次の操作 |
| --- | --- |
| ウィザードに ISO がない | ISO SR へのアップロード完了と、選択したプールやホストからのアクセスを確認します。 |
| 作成ボタンが無効 | プール、テンプレート、名前、リソース、ISO、ネットワーク、ディスク保存先を確認し、必須項目をすべて入力します。 |
| 作成や起動に失敗する | 表示されたタスクエラーを読みます。ホストの空き RAM、SR の空き容量、ホストからストレージとネットワークへのアクセスを確認します。再試行前に VM が既に作成されていないか確認してください。 |
| 再起動するたびにインストーラーが起動する | この VM の CD ドライブから ISO を取り出し、仮想ディスクに OS がインストールされたか確認します。 |
| ゲストのネットワークが使えない | 選択した仮想ネットワークとゲストの IP、ゲートウェイ、DNS を確認します。ゲストの問題調査中にホストの管理ネットワークを変更しないでください。 |
