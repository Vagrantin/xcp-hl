準備したテスト用コピーを再利用可能なテンプレートに変換し、別々の VM を 2 台作成してディスクとゲストデータを確認します。元の VM は変更せず保全します。

{{< callout type="info" >}}
イメージ `xoa-image-20261009-5f33c81`、パッケージ `v5.113.2_e281c536-ce38`、XO 5.113.2 (`e281c536`) のソースを確認したプレビューです。インストール済みアプライアンスでの変換・展開は未検証です。隔離したラボ用の手順であり、検証済みのゲスト OS 一般化や本番イメージ作成の手順ではありません。
{{< /callout >}}

## 始める前に

- XOA-HL 管理者アカウントと、通常のディスクを持つインストール済みの使い捨てゲストを使います。共有ディスクやパススルーデバイスは対象外です。変換には VM と所属プールの両方に管理権限が必要で、VM だけの権限では不十分です。
- [停止した VM のフルコピー手順](/docs/xoa-hl/vm-operations/#full-copy)で別の作業用コピーを作成します。元とコピーの UUID、ディスク VDI ID・SR・サイズ、重要でない確認用ファイルのチェックサムを記録します。コピーが隔離状態で起動することを確認し、正常終了させます。
- 作業用コピーの **NIC をすべて削除したまま**にし、インストーラー ISO を取り出し、自動電源オンを無効にしてラボのオブジェクトを無人実行ジョブの対象から外します。テンプレートとテスト展開 2 台に必要なホスト RAM、書き込み可能な SR 容量を確保します。アプライアンスや元の VM を変換しないでください。
- コンソール接続とラボゲストのログイン情報を用意します。VM 名や MAC を変更しても、コピーした認証情報、ホスト名、IP 設定、鍵、アプリケーションの識別情報は消去されません。これらのコピーはコンソールのみで使います。広く再利用する前に、OS 固有の準備、ライセンス、cloud-init、ゲストツールを別途検証する必要があります。

管理操作は**アプライアンスのアドレスを開いたブラウザー**で行います。ファイルとチェックサムの確認は**ゲストのコンソール内**で行い、ホストやアプライアンスでは実行しません。同じ基盤にあるテンプレートは独立したバックアップではありません。必要な[バックアップと復元の記録](/docs/xoa-hl/backup-restore/)は別に保全します。

## 1. 停止した作業用コピーだけを変換する {#convert-template}

1. 作業用コピーの UUID、停止状態（`Halted`）、空の NIC 一覧、記録したディスクを再確認します。`lab-template-v1` のような固有名を付け、説明にゲスト OS・バージョン、準備日、確認用チェックサムを記載します。変換前に更新して保存値を確認してください。
2. **詳細設定**タブ (`/#/vms/<copy-uuid>/advanced`) で **Convert to template** を選択します。VM が停止していないとボタンは無効です。ce38 ではボタンと確認画面は EN/FR/JA とも英語で、操作が確定的であると警告されます。対象が意図した使い捨てコピーでなければキャンセルします。
3. 一度だけ確定し、完了を待ちます。**ホーム**でオブジェクト種類を**テンプレート**にします (`/#/home?t=VM-template`)。必要に応じてフィルターを消し、対象行を展開して完全な UUID を読みます。作業用コピーと同じ UUID、予定した名前・説明であることを確認します。元の VM は別に残っている必要があります。

**確認：** 既存のコピーが**同じ UUID**のテンプレートになります。変換はコピー操作ではなく、別の VM を作成しません。サーバーはテンプレートフラグを設定する前にリムーバブルメディアの取り出しを試みます。取り出しエラーで変換が失敗しても、それ以前のメディア変更が残る場合があります。再試行前にオブジェクト種類、メディア、タスク状態を更新して確認します。UI による逆変換や自動ロールバックの手順は、このガイドでは確立していません。

## 2. テンプレートから停止した VM を作成する {#deploy-template}

1. **新規作成 → 仮想マシン(VM)** (`/#/vms/new`) で同じプールと記録したカスタムテンプレートを選びます。`lab-template-test-1` のような別名を使い、表示名だけでなく表示された URL の `template=` の UUID を照合します。
2. CPU・RAM、テンプレートの既存ディスク、サイズ、書き込み可能な展開先 SR を確認します。このラボでは予定したディスク構成とサイズを維持します。**インストール設定**で **No config drive** を選びます。インストーラーは実行せず、インストール済みディスクを再利用します。cloud-init がゲストの識別情報を変更するとも想定しません。予定した既存ディスクやこの選択肢がなければ、選んだテンプレートを再確認してください。
3. **ネットワークインタフェイス**で提案されたインターフェースをすべて削除し、一覧が空であることを確認します。NIC のないテンプレートでも、ウィザードはプールの既定ネットワークを提案する場合があります。サーバーはクローンした VIF を削除した後、フォームで指定したインターフェースを作成するため、それだけでは隔離を保証できません。
4. **詳細設定**で **Boot VM after creation** のチェックを外し、自動電源オンもオフのままにします。**概要**で **Fast clone** のチェックを外し、VM が 1 台、予定したディスク数・リソース・SR、**インターフェースが 0 個**であることを確認して、一度だけ **作成**します。作成後の起動と Fast clone は初期状態では有効なので、前回の設定を当てにしないでください。Fast clone がオフなら、このディスクテンプレートの経路はフルコピーを要求します。それでも容量が必要で、独立したバックアップを確立するものではありません。
5. 完了を待って更新し、新しい VM の UUID を記録します。起動前に停止状態（`Halted`）、空のネットワークタブ、予定したディスク数・サイズ・SR、テンプレートと元ディスクの記録とは異なる VDI ID を確認します。テンプレートと元 VM も残っているか確認してください。NIC が付いた、または VM が起動した場合はコピーを停止し、接続先への影響を調べてから続けます。

**確認：** ディスクを持ち、NIC がなく、停止した別の VM が存在します。成功通知や別名だけでは、目的のリソースやゲスト準備を証明できません。

## 3. 隔離した展開の再現性を確認する

1. 隔離状態を再確認してから `lab-template-test-1` だけを起動します。[コンソール](/docs/xoa-hl/vm-operations/#vm-console)でゲストの起動・ログイン、ディスク構成、記録したチェックサムを確認します。重要でない確認用ファイルだけを別のテスト値に変更し、記録して正常終了します。
2. **同じテンプレート**から `lab-template-test-2` として手順 2 を繰り返し、全設定を再確認します。停止中に別の VM UUID、異なる VDI ID、空の NIC 一覧を照合します。コンソールで起動し、確認用ファイルが test-1 の変更値ではなく元のチェックサムと一致することを確認して、正常終了します。
3. 両方の VM・VDI 一覧、テンプレート UUID、ゲストの結果、インストール済みリリースの識別情報を記録します。テスト VM は停止したままにしてください。終了時には各テスト VM だけを[特定した使い捨て VM の削除手順](/docs/xoa-hl/vm-operations/)で削除し、テンプレート、元 VM、必要なバックアップは保全します。

**確認：** 隔離した 2 台が予定したデータで起動し、test-1 の変更が test-2 の初期ファイルに影響していません。この小さなファイル確認は、アプリケーション復旧、OS の識別情報の一般化、対応ゲスト一覧の検証ではありません。ゲスト管理者が複製された識別情報を解消し、準備手順を別途検証するまで、本番ネットワークへ接続しないでください。

## 問題がある場合

- **変換を拒否される：** エラー、VM・プールの権限、実際の電源状態を読みます。重要なゲストを強制停止したり、識別が不確かなオブジェクトを何度も変換したりしないでください。エラー後は同じ UUID の種類とリムーバブルメディアを再確認します。
- **テンプレートが見つからない：** テンプレート種類、正しいプールとフィルターを選んで更新します。通常の VM 一覧にないことから削除済みと判断せず、記録を照合する前に別コピーを作成しないでください。
- **作成に失敗：** 再試行前にエラーとテンプレート・新 VM・VDI 一覧を保存します。ソースは失敗時の後片付けを登録しますが、応答の喪失や削除の失敗は、作成された全オブジェクトが消えた証拠にはなりません。孤立して見えるディスクを一括削除しないでください。
- **ゲストが異なる、起動しない：** テンプレートとログを保全し、UUID、コピーディスク構成、ファームウェア・リソース、構成方式を確認します。合格扱いにせず、ホスト管理ネットワークを変更して対処しないでください。

次の版は、新しい使い捨てコピーに版を含む別名を付け、隔離確認を繰り返して作成します。既存ゲストを直接保守する方法、テンプレートの廃止・削除、プール間の展開、Fast clone のストレージ動作、cloud-init、OS 固有の初期化は別の検証項目です。未解決の結果を保全して[機密情報を除いた記録を報告](/docs/xoa-hl/troubleshooting/#問題を報告する)してください。
