**XOA-HL アプライアンス**の管理者として、停止中の使い捨て VM で練習します。VM の識別情報、既存のディスクとインターフェースを記録します。十分な空き容量を持つ書き込み可能な SR と、XO の外部で隔離を確認した既存のネットワークを選びます。アプライアンス自体をテスト用ゲストにしないでください。

## 1. オブジェクトを識別する

| オブジェクト | 意味 |
| --- | --- |
| SR | 仮想ディスクを保存するストレージリポジトリ。空き容量を確認する |
| VDI | SR に保存された仮想ディスクのデータ |
| VBD | VM と仮想ディスクの接続 |
| VIF | VM の仮想ネットワークインターフェース |
| PIF | ホストのネットワークインターフェース。管理接続を変更するとホストとの接続を失う場合がある |

VM のインターフェースとホストの管理インターフェースは別です。ネットワークの選択や MAC の生成だけでは隔離できません。クローンや復元したゲストに使う前に、実際の VLAN、物理接続、ルーティングを確認します。

## 2. 小さな空のディスクを追加する

1. テスト VM の停止を確認します。**Disks** (`/#/vms/<id>/disks`) を開き、**New disk** を選びます。
2. 同じプール内の対象の書き込み可能な SR、明確なテスト名、単位を指定した小さなサイズを選びます。書き込み用のテストディスクでは読み取り専用を無効にします。作成を一度だけ実行し、完了を待ちます。
3. 新しい行で名前、サイズ、SR、対象 VM への接続を確認します。ディスクの識別情報と SR の空き容量を記録してからゲストを起動します。

ゲストのコンソールで、サイズとデバイス情報を使って新しいディスクを識別します。XO は仮想ディスクと接続を作成しますが、ゲスト内のパーティション作成、フォーマット、マウントは自動で行いません。ゲストのファイルシステム操作はこの検証の対象外です。推測したデバイス名だけを根拠にフォーマットしないでください。

作成に失敗したら、再試行前にタスクと VM/SR の一覧を確認します。途中まで完了した操作でディスクが残る場合があります。エラーを保存し、容量と接続を調べ、必要なら[トラブルシューティング](/docs/xoa-hl/troubleshooting/)を参照します。この練習ではディスクの縮小、拡張、ストレージ移行を検証しません。

## 3. 取り外しと削除を区別する

VBD の削除は VM からディスクを取り外します。VDI のデータを削除したことにはなりません。VDI の削除はディスクデータを破壊する別の操作で、この画面では接続中は利用できません。接続を切断する操作も、接続自体の削除とは異なります。

片付けるときはゲストを停止し、空のテストディスクだけを確実に識別します。内容が必要になる可能性があれば VDI を残してください。容量警告を解消するために起動ディスク、共有ディスク、識別できない VDI を削除しないでください。[重要なゲストデータは別にバックアップ](/docs/xoa-hl/backup-restore/)します。

## 4. 隔離した VM インターフェースを追加する

停止中のテスト VM で **Network** (`/#/vms/<id>/network`) を開き、**New device** を選びます。同じプール内の隔離を確認したネットワークを指定します。MAC 欄を空にして自動生成を使い、**Create** を選びます。起動前にインターフェース、ネットワーク、MAC を確認し、起動後にゲストの認識と予定した接続を確認します。

クローンや復元を隔離するときは、停止中に継承した VIF を**すべて削除**し、初回起動前に一覧が空であることを確認します。接続切り替えだけではなく、インターフェースの削除を使います。単なる切断はこの隔離手順ではありません。本番に到達しないことを確認し、コピーされた識別情報を解消してからテスト用ネットワークを追加します。

想定外の接続があれば、テスト VM を停止し、再試行前に接続先と外部の隔離を確認します。この VM インターフェース演習ではホストの PIF、管理アドレス、ボンド、VLAN を設定しません。練習中にホストの管理ネットワークを変更しないでください。[VM 操作](/docs/xoa-hl/vm-operations/)または[ホストとプールの管理](/docs/xoa-hl/hosts-pools/)に進めます。

別の使い捨てプール演習は[検証用 VLAN の作成](/docs/xoa-hl/storage-networks/#host-vlan-network)を参照してください。

## 5. NFS ISO ライブラリを接続する {#nfs-iso-library}

ISO SR はインストールメディアを保存します。VM ディスク用の書き込み可能な SR やバックアップ先とは別のものです。この演習では、提供元のチェックサムで確認したインストール ISO を含む、既存の専用 NFS エクスポートを接続します。NAS・エクスポートの準備とファイルの配置はストレージ管理者の作業で、このブラウザー手順の対象外です。このブラウザー手順では、ホストのシェルコマンドや管理ネットワークの設定変更は必要ありません。

作成する前に、目的のプールに適切な ISO SR がないか確認してください。識別情報、ホストからのアクセス、メディアが正しければ既存のものを使います。新しいテスト用ライブラリでは、NFS サーバー、正確なエクスポートパス、合意した NFS バージョン、対象プール・ホスト、ISO のファイル名・チェックサムを記録します。ISO を読む各ホストにはエクスポートへのアクセス許可が必要です。ブラウザーや XOA-HL アプライアンスだけからアクセスできても、ホストからのアクセスは確認できません。

1. 管理者として **新規作成 → ストレージ** (`/#/new/sr`) を開きます。対象プールのホストを選びます。`lab-nfs-iso` などの識別しやすい名前と、テスト用エクスポートを示す説明を入力します。
2. **ISO SR** の **NFS ISO** を選びます。VM ディスク用の **VDI SR** グループにある **NFS** は選びません。**Local** はハイパーバイザーホスト上のパスであり、手元のコンピューターやアプライアンスのフォルダーではありません。ローカル、SMB、ブロックデバイスの設定はこの演習の対象外です。
3. **SRサーバ** に NFS サーバーを入力します。ストレージ管理者と合意したバージョンを選びます (フォームには既定値、`4`、`4.1` があります)。サーバーの横の検索アイコンを使います。バージョンを変更しても再検出されないため、変更後はもう一度検索してください。合意した特定のオプションがなければ、最初のテストでは **Comma delimited NFS options** を空欄にします。このカタログでは NFS のバージョン・オプションのラベルは英語です。
4. **SRパス** で正確なエクスポートを選びます。この試行ではエクスポートのルートを使い、サブディレクトリの設定は対象外です。パスの確認が終わるまで待ちます。サーバー・エクスポートが見つからない、検出が失敗する、**SRの利用量** に既存の SR が表示される場合は、停止してエラーと識別情報を調べてください。このウィザードは NFS ISO にも NFS の検出処理を使います。検出された SR が ISO ライブラリであるとは限りません。再接続したり、既存ストレージ上への作成に関する警告を承認したりしないでください。
5. **SRの概要** で名前と選択したタイプ (`nfsiso`) を確認します。前のセクションで対象ホストとサーバー・パスをもう一度確認し、**作成** を 1 回だけ選びます。失敗した場合は、再試行する前にプールの SR 一覧を調べてください。SR やホストとの接続が一部だけ作成されている可能性があります。

作成した SR のバックエンドのタイプは `iso` で、`nfsiso` はウィザードの選択値です。SR の UUID を記録し、**Hosts** (`/#/srs/<id>/hosts`) を開きます。対象となる各ホストの状態が **Connected** で、表示された保存先がエクスポートと一致することを確認してください。共有 SR として設定されているだけでは、すべてのホストからのアクセスは確認できません。VM の実行ホストは、アクセスを確認した範囲内で選びます。

SR の更新操作 **Rescan all disks** を使い、要求の完了を待ってから **Disk/Disks** (`/#/srs/<id>/disks`) を開きます。想定した ISO の名前とサイズを確認します。ストレージ管理者がファイルを追加・置換した後は再スキャンしてください。ファイルの配置元で提供元のチェックサムを確認します。スキャンの成功やファイル名の一致は、整合性の確認にはなりません。

[VM 作成ウィザード](/docs/xoa-hl/create-vm/)で同じプールを選び、**ISO/DVD** に想定したメディアが表示されることを確認します。既にライブラリにある場合はブラウザーからのアップロードを省略してください。既存メディアの読み取りと新しいメディアのアップロードは別の機能です。インポート先の候補に表示されても、その SR・エクスポートが ISO の作成・書き込みを許可するとは限りません。アップロードのためにアクセス権を広く許可しないでください。

| 症状 | 確認と次の操作 |
| --- | --- |
| エクスポートが見つからない、パスの検出が失敗する | エラーを記録し、ストレージ管理者とサーバー・パス、バージョン、エクスポート検出、ホストからのアクセスを確認します。このエクスポートをウィザードで検出できなければ停止します。 |
| SR は作成されたがホストが未接続 | そのホストの接続・保存先とエクスポートへのアクセスを確認します。他のホストが接続されているだけでは不十分です。修復の試行として全ホストを切断しないでください。 |
| スキャンが成功しても ISO がない | 合意したエクスポートの完全なファイル、名前・サイズ、選択した SR を確認します。配置元を修正してから再スキャンし、SR を繰り返し作成しないでください。 |
| ISO/DVD に ISO がない | ウィザードのプール、ISO SR のタイプ、メディアの存在、対象ホストの接続を確認します。VM ディスク用の NFS SR は ISO SR ではありません。 |
| 作成失敗、予期しない SR が表示される | エラーと UUID・ホスト接続の一覧を保存します。再試行や削除の前に部分的なオブジェクトを識別します。原因不明のエラーを消すために SR の破棄・削除・フォーマットを使わないでください。 |

VM が使用中の ISO を削除したり、その SR を切断・破棄したりしないでください。使用している VM を記録し、テスト用ゲストからメディアを取り出してから片付けを計画します。この試行では、SR の破壊的な削除手順や ISO の書き込みアップロードの動作は検証しません。

## 6. VM ディスク用の NFS ストレージを作成する {#nfs-vm-storage}

この演習では、**VM ディスク用の書き込み可能な SR** を作成します。NFS ISO ライブラリはインストールメディア、NFS バックアップ先は独立したバックアップを保存するもので、ここで作成する SR とは用途が異なります。共有ストレージだけではバックアップにならず、マイグレーションや HA の準備完了も確認できません。

### 専用のエクスポートを準備する

ストレージ管理者が承認した、空の専用ラボ用エクスポートを使います。テストディスクの容量に加え、余裕を確保してください。NFS サーバー、正確なエクスポートのルート、合意したバージョン・オプション、プールと対象の全ホストを記録します。ストレージ管理者は各ホストの読み書きを許可し、サーバーの空き容量とクォータを確認します。ISO 用エクスポート、バックアップ先、用途不明のデータがあるエクスポートは流用しません。NAS の設定やホストネットワークの変更はこのブラウザー演習の対象外です。

**XOA-HL アプライアンス**に管理者でログインします。作成・検出 API では選択したホストの管理権限が必要です。最初に既存の SR 一覧を記録します。目的のストレージが既に同じプールにあれば、別の SR を作らず、その UUID とホストからのアクセスを確認します。SR の作成自体に既存の VM は必要ありません。その後のディスク検証では、停止中の使い捨て VM、独立したコンソール接続、重要なデータの独立したバックアップを用意します。最初の VM の場合は、以下の SR の確認を終えてから、その SR 上に [VM を作成して OS をインストール](/docs/xoa-hl/create-vm/)し、ここに戻ってください。XOA-HL 自体をテスト VM にしないでください。

### SR を作成して状態を確認する

1. **新規作成 → ストレージ** (`/#/new/sr`) を開き、対象プールのホストを選びます。`lab-nfs-vdis` などの識別しやすい名前と、エクスポートを示す説明を入力します。**VDI SR** の **NFS** を選択し、**ISO SR** の **NFS ISO** が選ばれていないことを確認します。
2. **SRサーバ** に入力し、合意した NFS バージョン (既定値、`4`、`4.1`) を選んでサーバーの検索アイコンを使います。特定の設定に合意していなければ **Comma delimited NFS options** は空欄にします。サーバーやバージョンを変えた場合は、再検出とパス選択をやり直してください。バージョンの変更だけではエクスポートを再検出しません。このカタログでは NFS バージョン・オプションのラベルは英語です。
3. **SRパス** で正確なエクスポートのルートを選び、サブディレクトリは使わず、検出の完了を待ちます。**SRの利用量** を確認します。既存 SR の UUID や使用中の項目が表示されたら停止し、ストレージ所有者と識別してください。再接続や、その上への別 SR の作成は選びません。NFS の作成処理では、他の一部タイプで使われる既存ストレージの確認を**要求しません**。警告がないことは、エクスポートが空である証明にはなりません。
4. **SRの概要** で名前、タイプ `nfs`、パスを確認します。前のセクションでホスト、サーバー、バージョン、オプションを再確認し、**作成** を 1 回だけ選んで完了を待ちます。失敗した場合は、再試行前に SR とホスト接続の一覧を調べます。要求が失敗してもオブジェクトが残る可能性があります。
5. 作成した SR の UUID を記録します。**一般** (`/#/srs/<id>/general`) で `Type: nfs`、サイズ、使用量・空き容量、対象プールを確認します。**Hosts** (`/#/srs/<id>/hosts`) で対象の各ホストと接続 (PBD) を記録し、**Connected**、設定の `server` と `serverpath`、指定した場合は `nfsversion`・`options` を確認します。共有の宣言や 1 台の接続だけでは全ホストを確認できません。対象の接続がない、または未接続なら、そのホストでの割り当てや移動を始めず停止します。状態ボタンは操作も実行するため、確認のためにクリックしないでください。

### 使い捨てディスクを確認する

停止中のテスト VM で、[小さな空のディスクを追加する](#2-小さな空のディスクを追加する)手順に従い、この SR を正確に選びます。VM、VDI、接続の識別情報を記録し、ディスクの SR とサイズを再確認します。接続を確認したホストでのみゲストを起動してください。サイズとデバイス情報から追加ディスクを識別します。ゲスト内のパーティション作成・フォーマット・マウントには、OS 別の手順と確実なデバイス識別が必要です。

ゲスト管理者がその**テストディスク**を準備した場合は、重要でないサンプルファイルを書き込み、チェックサムを記録します。作業を保存し、ゲストを通常の方法で停止・起動してから、同じディスク、ファイル、チェックサムを確認します。この結果は独立したバックアップ・復元テストとは分けて記録してください。空ディスクの割り当てや再スキャンの成功だけでは、ゲストの書き込みと永続性を確認できません。プール全体でのアクセスを主張する前に、別途承認された配置・マイグレーション演習で対象の各ホストから読み書きを検証してください。

### 障害に対応し、片付けを計画する

| 症状 | 確認と次の操作 |
| --- | --- |
| エクスポートがない、検出失敗 | 正確なエラーと選択したホスト・サーバー・パス・バージョンを保存します。ストレージ管理者に検出、ホストの権限、接続を確認してもらいます。回避のためにローカル・ブロックストレージへ切り替えたり権限を広げたりしません。 |
| 既存 SR を検出、作成失敗 | 検出・作成された全 SR の UUID と接続を、部分的なオブジェクトも含めて記録します。再試行や再接続の判断前に、所有者と現在の利用状況を確認します。 |
| タイプ・パスが違う、ホストが未接続 | 新規割り当てを止め、記録したエクスポートと各ホスト接続を比較します。診断のために全ホストを切断したり SR を削除したりしません。 |
| 容量警告、ディスク書き込み失敗 | SR 使用量、サーバーの空き容量・クォータ、実行中タスク、ゲスト内の対象ディスクを確認します。証拠とデータを保持し、用途不明のディスク・スナップショット・NAS ファイルを削除しません。 |

片付ける際は最終的なオブジェクト一覧を保存し、テスト VM を通常の方法で停止します。確実に識別したテストディスクだけに、前述の[取り外しと削除の区別](#3-取り外しと削除を区別する)を適用します。全利用者と復旧要件を所有者と確認できるまでは SR・エクスポートを保持してください。この演習では SR の破壊・登録解除・再接続、NAS ファイルの削除、既定ストレージの変更手順を提供しません。ローカル・SMB・iSCSI の設定、NFS サブディレクトリ、障害・性能、プール全体のマイグレーション・HA は個別の検証が必要です。

## 7. 専用の予備アップリンクに検証用 VLAN を作成する {#host-vlan-network}

これは **ホスト・プールの設定**を伴う演習です。**XOA-HL のブラウザー**からタグ付きのゲストネットワークを 1 つ作成します。使い捨てプール、専用の予備物理アップリンク、停止中の使い捨て VM を用意し、独立したホストコンソールを常に利用できる状態にします。開始前に、プール・マスター・対象の全ホスト、既存ネットワークと PIF の UUID、デバイス名、MAC、VLAN、MTU、管理フラグ、IP モードと接続状態を記録します。

ネットワーク管理者に VLAN ID、タグ付きスイッチポート、MTU `1500`、ゲストのアドレス、許可・禁止する接続先を承認してもらいます。対象の **各ホスト**で予備アップリンクを確認し、管理・ストレージ・バックアップ・他の処理で未使用、ホスト IP 設定なし、ボンドや既存 VLAN 構成への所属なしを確認します。配線・スイッチの台帳とも比較してください。デバイス名や Management 表示がないことだけでは不十分です。構成を確認できなければ中止します。VLAN 番号だけでは隔離を証明できず、スイッチポート、ルーティング、DHCP、DNS、ファイアウォールも設定されません。

### ネットワークを一度だけ作成する

1. 管理者として **新規作成 → Network** (`/#/new/network`) を開き、使い捨ての **プール**を選びます。API はプールの管理権限を要求します。**Bonded network** と **Private network** はオフにします。Private network は別の SDN 手順です。
2. **Info → Interface** で記録した **プールマスターの予備 PIF** を明示的に選びます。選択欄はマスターの VLAN なし PIF に限定し、ボンドのスレーブを除外しますが、管理用 PIF は**除外しません**。UUID・デバイス・MAC を独立した台帳と再確認します。Interface を空にするとアップリンクなしのネットワークになり、今回の VLAN は作成できません。
3. 検証用途を識別できる **Name** と **Description** を入力します。**MTU** は `1500`、**VLAN** は承認されたタグ付き VLAN ID を正確に指定します。VLAN を空にしたり `0` を代用したりしません。ブラウザーで空欄は API の既定値 `0` になります。**No NBD Connection** を選びます。このゲストネットワークに NBD 用途は不要です。
4. プール、マスター PIF、VLAN、MTU、2 つの種類スイッチを見直して **Create network** を一度だけ選びます。完了し、プールの **ネットワーク** (`/#/pools/<id>/network`) が表示されるまで待ちます。失敗時はエラーを保存し、再試行前にプールのネットワークと全ホストの PIF を調べます。サーバーは作成失敗時にネットワークの後処理を試みますが、プール側の全変更が元に戻った証拠にはなりません。

### 対象の各ホストを確認する

プールの行にあるコピー操作から新規ネットワークの UUID を取得し、名前・MTU・VLAN を記録します。行の PIF・VLAN の概要は **マスター**の情報で、他ホストの設定を証明しません。**PIFs** を展開してホスト・デバイス・MAC を台帳と比較します。ここでの状態表示は **物理リンク**を示し、ホストのネットワークにある **Connected** ボタンは PIF の接続状態を示します。どちらもタグ付き通信の成功を証明しません。状態を読むために接続・切断を押さないでください。

対象の各ホストで **ネットワーク** (`/#/hosts/<id>/network`) を開き、新規ネットワークの PIF を探します。UUID、デバイス・MAC、VLAN、MTU、管理表示、IP モード・アドレス、状態を記録し、承認された VLAN、MTU `1500`、接続済み、予定した物理リンク、ホスト IP・管理用途なしを確認します。管理とストレージの接続も開始前と比較します。PIF がない・切断中・想定外ならゲスト配置前に中止します。修復目的で既存の VLAN・MTU・IP 欄や親 PIF のスイッチを変更しません。

### ゲストの通信を検証して証拠を保存する

停止中の使い捨て VM で、前述の [VM インターフェース追加手順](#4-隔離した-vm-インターフェースを追加する)に従い、このネットワークを正確に選びます。VM・VIF の UUID、MAC、ネットワーク、実行ホストを記録し、引き継いだインターフェースが検証構成を迂回していないことを確認します。PIF を確認したホストだけで起動します。ゲスト管理者がコンソールから承認済みの**タグなしゲストインターフェース**と重複しない IP 設定を構成します。この演習ではゲストの VLAN トランクを設定しません。

ゲストのアドレス、サブネット、経路、DNS を別々に確認します。許可した相手・サービスと、管理者が指定した禁止先（本番への経路を含む）を検証します。ping の失敗だけでは隔離を証明できません。実際の試験と結果を記録し、正常停止・起動後も対応関係と通信を再確認します。同じホスト上の相手との通信だけでは物理アップリンクや他ホストを証明できません。ホスト間通信とマイグレーションはそれぞれ承認された別の構成で検証します。検証中もホスト管理、ストレージ、XOA-HL へのアクセスを確認してください。

| 症状 | 確認と次の操作 |
| --- | --- |
| 予備 PIF がない、プールが違う | マスター、物理デバイス、ボンド・VLAN の所属を確認します。中止し、選択欄を回避するため管理・ストレージ PIF や別プールを選びません。 |
| エラー、重複ネットワーク、一部 PIF しかない | 時刻・エラーと全ホストの正確なネットワーク・PIF UUID を保存します。再試行前に所有者と照合し、通知だけでロールバック済みと判断しません。 |
| 物理リンクはあるが予定した通信ができない | 接続状態、VIF の対応、ゲストの IP・経路・DNS、承認されたタグ付きスイッチ経路、相手・ファイアウォールを確認します。推測でホストの管理 IP、親 MTU、VLAN を変更しません。 |
| 想定外の本番アクセス、管理・ストレージ切断 | テストゲストを停止して証拠を保存し、ネットワーク管理者の復旧計画と独立したホストコンソールを使います。構成が不明なままブラウザーで変更を続けません。 |

最終台帳を保存し、テスト VM を正常停止します。前の手順で必要な場合は確実に識別したテスト VIF だけを取り外します。所有者が全利用者を確認し、承認済みの撤去・復旧手順を用意するまでネットワーク・PIF・スイッチ設定を保持します。ネットワーク削除、VLAN・MTU 編集、PIF 削除、ボンド、管理経路の移行、ホスト IP 設定はこの演習の対象外です。既存ネットワークの MTU 変更ではインターフェースの切断・再接続が起こり得ます。[ホスト・プール](/docs/xoa-hl/hosts-pools/)と[トラブルシューティング](/docs/xoa-hl/troubleshooting/)も参照してください。実環境での作成・通信・隔離・復旧の検証は未完了です。
