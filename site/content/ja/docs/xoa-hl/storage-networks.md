VM へのディスクやネットワークインターフェースの追加、ISO ファイルや VM ディスク用の NFS ストレージの接続、VLAN ネットワークの作成を行います。**XOA-HL アプライアンス**に管理者としてログインし、停止中のテスト VM で練習してください。アプライアンス自体では行いません。始める前に、VM の ID、ディスク、ネットワークインターフェースを控えます。

## オブジェクトを知る {#objects}

| オブジェクト | 内容 |
| --- | --- |
| SR | ストレージリポジトリ。仮想ディスクの保存場所です。空き容量を確認します |
| VDI | SR に保存された仮想ディスク |
| VBD | VM とその仮想ディスクの 1 つをつなぐもの |
| VIF | VM の仮想ネットワークインターフェース |
| PIF | ホストのネットワークインターフェース。ホストの管理ネットワークを変更すると、ホストに接続できなくなることがあります |

VM のネットワークインターフェースは、ホストの管理インターフェースとは別のものです。ネットワークを選ぶことや新しい MAC アドレスを生成することでは、VM は隔離されません。クローンや復元したゲストを接続する前に、実際の VLAN、物理アップリンク、ルーティングを確認します。

## 小さな空のディスクを追加する {#add-disk}

1. テスト VM が停止していることを確認します。**Disks**（`/#/vms/<id>/disks`）を開き、**新規仮想ディスクを作成** を選びます。
2. 同じプール内の書き込み可能な SR、分かりやすいテスト用の名前、単位付きの小さなサイズを選びます。読み取り専用のオプションはオフのままにします。ディスクを 1 回だけ作成し、完了を待ちます。
3. 新しい行で、名前、サイズ、SR、接続先の VM を確認します。ゲストを起動する前に、ディスクの ID と SR の残りの空き容量を控えます。

ゲストのコンソールで、サイズとデバイス情報から新しいディスクを見つけます。XO はディスクを作成して接続しますが、ゲスト内でのパーティション作成、フォーマット、マウントは行いません。それは OS ごとに異なる別の作業です。推測したデバイス名だけを根拠にフォーマットしないでください。

作成に失敗した場合は、再試行する前にタスクと、VM と SR のディスク一覧を確認します。途中で止まった操作がディスクを残すことがあります。エラーを保存し、空き容量と接続を確認し、必要なら[トラブルシューティング](/docs/xoa-hl/troubleshooting/)を参照します。ディスクの縮小、拡張、移動はここでは扱いません。

## ディスクを取り外す、または削除する {#detach-vs-delete}

VBD を削除すると、ディスクは VM から取り外されますが、そのデータ（VDI）は残ります。VDI を削除するとデータが消えます。これは別の操作で、ディスクが接続されている間、この画面には表示されません。接続を切断することも、接続を削除することとは異なります。

片付けるときは、ゲストを停止し、空のテストディスクを確実に特定します。内容が役に立つ可能性があれば、VDI は残します。容量の警告を消すために、起動ディスク、共有ディスク、特定できないディスクを削除しないでください。[大切なゲストデータは別にバックアップ](/docs/xoa-hl/backup-restore/)します。

## 隔離したネットワークインターフェースを追加する {#add-vif}

1. 停止中のテスト VM で **ネットワーク**（`/#/vms/<id>/network`）を開き、**New device** を選びます。
2. 隔離を確認した、同じプール内のネットワークを選びます。MAC アドレスは空のままにして自動生成させ、**Create** を選びます。
3. VM を起動する前に、新しいインターフェース、そのネットワーク、MAC アドレスを確認します。起動後、ゲストがインターフェースを認識し、予定どおりの通信ができることを確認します。

クローンや復元したコピーを隔離するには、VM の停止中に、引き継いだ VIF を**すべて**削除し、最初の起動前に一覧が空であることを確認します。接続の切り替えではなく、削除の操作を使います。切断しただけのインターフェースは隔離されたことになりません。テスト用ネットワークは、本番に届かないことを確認し、コピーされたゲストの識別情報を整理してから追加します。

VM が想定外の場所に届く場合は、VM を停止し、選んだネットワークと XO の外での隔離を確認してから再試行します。この手順では、ホストのインターフェース（PIF）、管理アドレス、ボンド、VLAN は設定しません。手順の途中でホストの管理ネットワークを変更しないでください。ホスト上の VLAN については[予備のアップリンクに検証用 VLAN を作成する](/docs/xoa-hl/storage-networks/#host-vlan-network)を参照してください。VM のその他の作業は[VM の管理](/docs/xoa-hl/vm-operations/)または[ホストとプール](/docs/xoa-hl/hosts-pools/)を参照してください。

## NFS ISO ライブラリを接続する {#nfs-iso-library}

ISO SR はインストールメディアを保存します。VM ディスク用の書き込み可能な SR とも、バックアップの保存先とも異なります。この手順では、提供元のチェックサムで確認済みのインストール ISO が入った、既存の専用 NFS エクスポートを接続します。エクスポートの準備とファイルの配置はストレージ管理者が行います。あなたはブラウザーで作業するだけで、ホスト上では何も変更しません。

**始める前に**

- プールに適した ISO SR が既にないか確認します。識別情報、ホストからのアクセス、メディアが正しければ、それを使います。
- 新しいライブラリでは、NFS サーバー、正確なエクスポートパス、ストレージ管理者と合意した NFS バージョン、プールとホスト、ISO のファイル名とチェックサムを控えます。
- ISO を読み込む各ホストに、エクスポートへのアクセス許可が必要です。ブラウザーやアプライアンスからアクセスできても、ホストから届くことの証明にはなりません。

1. 管理者として **新規作成 → ストレージ**（`/#/new/sr`）を開きます。プール内のホストを選びます。`lab-nfs-iso` のような分かりやすい名前と、テスト用エクスポートが分かる説明を入力します。
2. **ISO SR** の **NFS ISO** を選びます。**VDI SR** グループの **NFS** は選びません。こちらは VM ディスク用のストレージを作成します。**Local** はハイパーバイザーホスト上のフォルダーで、手元のコンピューターやアプライアンス上のフォルダーではありません。ローカル、SMB、ブロックストレージはここでは扱いません。
3. **SRサーバ** に NFS サーバーを入力します。合意した NFS バージョンを選び（フォームには既定値、`4`、`4.1` があります）、サーバーの横の検索アイコンを選びます。バージョンを変えても再検索されないため、変更したら検索し直します。オプションを合意していなければ、**Comma delimited NFS options** は空のままにします。
4. **SRパス** で正確なエクスポートを選びます。エクスポートのルートを使います（サブフォルダーは扱いません）。パスの確認を待ちます。エクスポートがない、確認に失敗する、**SRの利用量** に既存の SR が表示される場合は、作業を止めてエラーと ID を調べます。このウィザードは ISO ライブラリでも NFS の確認を行うため、検出された SR が ISO ライブラリとは限りません。その SR を再接続したり、既存ストレージ上への作成に関する警告を受け入れたりしないでください。
5. **SRの概要** で名前と選んだタイプ（`nfsiso`）を確認します。上のホスト、サーバー、パスをもう一度確認し、**作成** を 1 回だけ選びます。失敗した場合は、再試行する前にプールの SR 一覧を確認します。失敗した要求が、途中まで作られた SR やホストとの接続を残すことがあります。
6. 新しい SR の UUID を控えます。内部のタイプは `iso` です（`nfsiso` はウィザードでの選択肢にすぎません）。**Hosts**（`/#/srs/<id>/hosts`）を開き、各ホストの接続が Connected で、正しいエクスポートを示していることを確認します。共有 SR であっても、すべてのホストから届くとは限りません。アクセスを確認したホストでのみ VM を実行します。
7. SR の **Rescan all disks** 操作を使い、完了を待ってから **Disks**（`/#/srs/<id>/disks`）を開きます。ISO の名前とサイズを確認します。ストレージ管理者がファイルを追加・置換するたびに、再スキャンします。提供元のチェックサムは配置元で確認します。スキャンの成功や名前の一致は、ファイルが壊れていないことの証明にはなりません。

**確認:** [VM 作成ウィザード](/docs/xoa-hl/create-vm/)で同じプールを選び、**ISO/DVD** に想定したメディアが表示されることを確認します。表示されれば、ブラウザーからのアップロードは不要です。既存メディアの読み込みと新しいメディアのアップロードは別の機能です。インポートの一覧に表示されても、この SR が新しい ISO ファイルを受け付けるとは限りません。アップロードのためにアクセス権を広げないでください。

| 症状 | 確認すること |
| --- | --- |
| エクスポートが見つからない、またはパスの確認に失敗する | エラーを控えます。ストレージ管理者と一緒に、サーバー、パス、NFS バージョン、エクスポートの検出、ホストからのアクセスを確認します。ウィザードがこのエクスポートを見つけられなければ、作業を止めます。 |
| SR はあるが、ホストが未接続 | そのホストの接続、パス、エクスポートへのアクセスを確認します。他のホストが接続されていても十分ではありません。修復のつもりで全ホストを切断しないでください。 |
| スキャンは成功するが、ISO がない | 合意したエクスポートに完全なファイルがあるか、その名前とサイズ、選んだ SR を確認します。配置元を直してから再スキャンします。SR を何度も作り直さないでください。 |
| ISO/DVD に ISO が表示されない | ウィザードのプール、SR が ISO SR であること、メディアがあること、ホストの接続を確認します。VM ディスク用の NFS SR は ISO SR ではありません。 |
| 作成に失敗する、または想定外の SR が表示される | エラーと、SR の UUID とホスト接続の一覧を保存します。再試行や片付けの前に、途中まで作られたオブジェクトを特定します。原因不明のエラーを消すために、登録解除、削除、フォーマットを使わないでください。 |

VM が使っている間は、ISO を削除したり、その SR を切断・登録解除したりしないでください。どの VM が使っているかを控え、テスト用ゲストからメディアを取り出してから片付けを計画します。SR の削除と ISO のアップロードはここでは扱いません。

## VM ディスク用の NFS ストレージを作成する {#nfs-vm-storage}

**VM ディスク用の書き込み可能な SR** が必要なときに使います。NFS ISO ライブラリはインストールメディアを、NFS のバックアップ先はバックアップを保存します。どちらもここで作成する SR ではありません。共有ストレージだけではバックアップにならず、マイグレーションや高可用性（HA）の準備ができたことにもなりません。

### 専用のエクスポートを準備する

- ストレージ管理者が承認した、空の検証専用エクスポートを使います。テストディスクと余裕分の容量が必要です。
- NFS サーバー、正確なエクスポートのルート、合意したバージョンとオプション、プール、それを使う全ホストを控えます。
- ストレージ管理者は、それらのホストからの読み書きを許可し、サーバーの空き容量とクォータを確認する必要があります。
- ISO 用のエクスポート、バックアップ先、中身の分からないデータがあるエクスポートは使い回さないでください。

**XOA-HL アプライアンス**に管理者としてログインします。ストレージの作成と確認には、選んだホストの管理者権限が必要です。まず既存の SR を控えます。そのストレージがプールに既にあれば、別の SR を作らず、その UUID とホストからのアクセスを確認します。SR の作成に VM は必要ありません。最初の VM をここに置く場合は、下の手順で SR を作成して確認し、その上に [VM を作成して OS をインストール](/docs/xoa-hl/create-vm/)してから、ディスクのテストのためにここに戻ります。XOA-HL 自体をテスト VM にしないでください。

### SR を作成して確認する

1. **新規作成 → ストレージ**（`/#/new/sr`）を開き、プール内のホストを選び、`lab-nfs-vdis` のような分かりやすい名前とエクスポートの説明を入力します。**VDI SR** の **NFS** を選びます。**ISO SR** の **NFS ISO** が選ばれていないことを確認します。
2. **SRサーバ** を入力し、合意した **NFS version**（既定値、`4`、`4.1`）を選び、サーバーの検索アイコンを選びます。オプションを合意していなければ、**Comma delimited NFS options** は空のままにします。サーバーやバージョンを変えた場合は、検索とパスの選択をやり直します。バージョンを変えただけでは、エクスポートは再確認されません。
3. **SRパス** でサブフォルダーを含まない正確なエクスポートのルートを選び、確認を待ちます。**SRの利用量** を見ます。既存の SR の UUID や使用中の項目が表示されたら、作業を止め、ストレージの所有者と一緒に特定します。その SR を再接続したり、その上に別の SR を作ったりしないでください。NFS では、XO は既存ストレージの確認を**求めません**。警告が出ないことは、エクスポートが空であることの証明にはなりません。
4. **SRの概要** で名前、タイプ `nfs`、パスを確認します。上のホスト、サーバー、バージョン、オプションをもう一度確認し、**作成** を 1 回だけ選んで待ちます。失敗した場合は、再試行する前に SR とホスト接続の一覧を確認します。失敗した要求がオブジェクトを残すことがあります。
5. 新しい SR の UUID を控えます。**一般**（`/#/srs/<id>/general`）で、`Type: nfs`、サイズ、使用量と空き容量、プールを確認します。
6. **Hosts**（`/#/srs/<id>/hosts`）を開きます。各ホストについて接続（PBD）を控え、**Connected** と表示され、`server` と `serverpath`（設定した場合は `nfsversion` と `options` も）が正しいことを確認します。1 台が接続されていても、他のホストも接続されているとは限りません。接続がない、または未接続なら、そこに VM を置く前に作業を止めます。状態の表示はボタンでもあります。クリックせずに読み取ってください。

### 新しい SR でディスクをテストする

1. 停止中のテスト VM で[小さな空のディスクを追加する](#add-disk)に従い、この SR を選びます。VM、ディスク、接続の ID を控え、ディスクの SR とサイズを確認します。
2. 接続を確認したホストでのみゲストを起動します。サイズとデバイス情報から追加したディスクを見つけます。パーティション作成、フォーマット、マウントには、OS ごとの手順と、デバイスの確実な特定が必要です。
3. ゲストの管理者がこの**テストディスク**を準備した場合は、重要でないサンプルファイルを書き込み、そのチェックサムを控えます。作業を保存し、ゲストを通常どおりシャットダウンしてから再び起動し、同じディスク、ファイル、チェックサムを確認します。

**確認:** 再起動後もファイルとチェックサムが変わっていません。空のディスクや再スキャンの成功だけでは、書き込みができ、その内容が残ることは証明できません。この結果は、バックアップと復元のテストとは分けて記録します。プール全体でこのストレージを使えると判断する前に、別途承認された配置またはマイグレーションのテストで、各ホストから読み書きのテストを繰り返します。

### 問題が起きた場合

| 症状 | 確認すること |
| --- | --- |
| エクスポートがない、または確認に失敗する | 正確なエラーと、選んだホスト、サーバー、パス、バージョンを保存します。ストレージ管理者に、検出、ホストの権限、接続を確認してもらいます。回避策としてローカルやブロックのストレージに切り替えたり、権限を広げたりしないでください。 |
| 既存の SR が検出される、または作成に失敗する | 途中まで作られたものも含め、すべての SR の UUID と接続を控えます。再試行や再接続の前に、所有者と使用状況を確認します。 |
| タイプやパスが違う、またはホストが未接続 | 新しい割り当てを止めます。控えたエクスポートと各ホストの接続を比べます。診断のために全ホストを切断したり、SR を削除したりしないでください。 |
| 容量の警告が出る、またはゲストでの書き込みに失敗する | SR の使用量、サーバーの空き容量とクォータ、実行中のタスク、ゲスト内の対象ディスクを確認します。証拠とデータを残します。NAS 上の特定できないディスク、スナップショット、ファイルを削除しないでください。 |

片付けるときは、オブジェクトの最終的な一覧を保存し、テスト VM を通常どおりシャットダウンします。[ディスクを取り外す、または削除する](#detach-vs-delete)は、確実に特定したテストディスクにだけ適用します。所有者がすべての利用者と復旧の必要性を洗い出すまで、SR とエクスポートは残します。SR の破棄、登録解除、再接続、NAS 上のファイルの削除、既定のストレージの変更はここでは扱いません。ローカル、SMB、iSCSI のストレージ、NFS のサブフォルダー、障害、性能、プール全体のマイグレーションや HA も扱いません。

## 予備のアップリンクに検証用 VLAN を作成する {#host-vlan-network}

この手順は**ホストとプールの設定を変更します**。**XOA-HL のブラウザー**から、タグ付きのゲストネットワークを 1 つ作成します。テスト用のプール、専用の予備の物理アップリンク、停止中のテスト VM を使います。作業中は常に、別のホストコンソールを使える状態にしておきます。

**始める前に**

- プール、そのマスター、各ホストと、既存のネットワークと PIF の UUID、デバイス名、MAC アドレス、VLAN、MTU、管理フラグ、IP モード、接続状態を控えます。
- ネットワーク管理者に、VLAN ID、タグ付きのスイッチポート、MTU `1500`、ゲストのアドレス、許可する接続先と禁止する接続先を承認してもらいます。
- **各**ホストで予備のアップリンクを確認します。管理、ストレージ、バックアップ、その他の通信に使われておらず、ホストの IP アドレスがなく、ボンドや既存の VLAN に含まれていないこと。配線とスイッチの記録と照合します。デバイス名や、Management の表示がないことだけでは不十分です。
- この構成を確認できない場合は、作業を止めます。VLAN 番号だけでは何も隔離されず、スイッチポート、ルーティング、DHCP、DNS、ファイアウォールも設定されません。

### ネットワークを 1 回だけ作成する

1. 管理者として **新規作成 → Network**（`/#/new/network`）を開き、テスト用の **プール** を選びます（プールの管理者権限が必要です）。**Bonded network** と **Private network** はオフのままにします。Private network は別の SDN 機能です。
2. **Info → Interface** で、控えておいた**プールマスターの予備 PIF** を選びます。一覧には VLAN のないマスターの PIF が表示され、ボンドのメンバーは表示されませんが、管理用の PIF は**表示されます**。UUID、デバイス、MAC を記録と照合します。Interface を空にしないでください。空にするとアップリンクのないネットワークになり、目的の VLAN にはなりません。
3. 検証用と分かる **Name** と **Description** を入力します。**MTU** を `1500` に、**VLAN** を承認されたタグ付き VLAN の正確な ID に設定します。VLAN を空にしたり `0` を使ったりしないでください。空欄は `0` として送信されます。**No NBD Connection** を選びます。このゲストネットワークに NBD は不要です。
4. プール、マスターの PIF、VLAN、MTU、ネットワークの種類を決める 2 つのスイッチを見直し、**Create network** を 1 回だけ選びます。完了して、プールの **ネットワーク** 画面（`/#/pools/<id>/network`）が表示されるまで待ちます。失敗した場合は、エラーを保存し、再試行する前にプールのネットワークと各ホストの PIF を確認します。XO は作成に失敗すると後片付けを試みますが、プール内のすべての変更が元に戻ったことの証明にはなりません。

### 各ホストを確認する

1. プールの画面で新しいネットワークの行から UUID をコピーし、名前、MTU、VLAN を控えます。この行の PIF と VLAN の概要は**マスター**だけの情報です。
2. **PIFs** を展開し、各ホスト、デバイス、MAC アドレスを記録と照合します。ここの状態アイコンは**物理リンク（キャリア）**を示します。ホストのネットワークタブにある **Connected** ボタンは、PIF が接続されているかを示します。どちらも、タグ付きの通信が流れることの証明にはなりません。状態を読むためだけに、接続や切断をクリックしないでください。
3. 各ホストで **ネットワーク**（`/#/hosts/<id>/network`）を開き、新しいネットワークの PIF を見つけ、UUID、デバイス、MAC、VLAN、MTU、管理の表示、IP モードとアドレス、状態を控えます。承認された VLAN、MTU `1500`、接続済みの状態、想定どおりのリンク、ホストがそこで IP アドレスを使っていないことを確認します。
4. 管理とストレージの接続を、開始前の記録と比べます。

PIF がない、切断されている、または想定外の場合は、ゲストを置く前に作業を止めます。直すために、既存の VLAN、MTU、IP の欄を編集したり、親の PIF を切り替えたりしないでください。

### ゲストの通信を確認する

1. 停止中のテスト VM で[隔離したネットワークインターフェースを追加する](#add-vif)に従い、このネットワークを正確に選びます。VM と VIF の UUID、MAC アドレス、ネットワーク、VM を実行するホストを控えます。引き継いだインターフェースが検証用の構成を迂回していないことを確認します。
2. PIF を確認したホストでのみ VM を起動します。ゲストの管理者が、合意した**タグなしのインターフェース**と重複しない IP 設定を、コンソールから構成します。この手順では、ゲスト内の VLAN トランクは設定しません。
3. ゲストのアドレス、サブネット、経路、DNS を個別に確認します。承認された 1 つの相手またはサービスと、管理者が示した禁止先（本番を含む）をテストします。ping の失敗は隔離の証明にはなりません。実施したテストと結果を控えます。
4. ゲストを通常どおりシャットダウンして再び起動し、確認を繰り返します。

**確認:** ゲストは承認された相手に届き、禁止先には届かず、再起動後も同じ状態です。作業の間ずっと、ホストの管理、ストレージ、XOA-HL に接続できています。同じホスト上の相手との通信では、物理アップリンクや他のホストはテストできません。ホスト間の通信とマイグレーションには、それぞれ承認された別のテストが必要です。

| 症状 | 確認すること |
| --- | --- |
| 予備の PIF がない、またはプールが違う | マスター、物理デバイス、ボンドや VLAN への所属を確認します。作業を止めます。一覧を回避するために、管理用やストレージ用の PIF を選んだり、プールを変えたりしないでください。 |
| エラーが出る、ネットワークが重複する、一部のホストに PIF がない | 時刻、エラー、各ホストのネットワークと PIF の正確な UUID を保存します。再試行する前に所有者と確認します。通知だけでは、変更が元に戻ったことの証明にはなりません。 |
| リンクは上がっているが、ゲストに想定した通信がない | 接続状態、VIF の対応、ゲストの IP、経路、DNS、承認されたタグ付きのスイッチ経路、相手とファイアウォールを確認します。推測で、ホストの管理 IP、親の MTU、VLAN を変更しないでください。 |
| 想定外に本番に届く、または管理やストレージへの接続を失う | テスト用ゲストを停止し、証拠を残し、ネットワーク管理者の復旧計画に沿って別のホストコンソールを使います。構成が不確かな間は、ブラウザーで他の変更をしないでください。 |

終えるときは、最終的な記録を保存し、テスト VM を通常どおりシャットダウンします。特定したテスト用 VIF は、上の手順で必要な場合にだけ削除します。所有者がすべての利用者を洗い出し、撤去と復旧の計画を承認するまで、ネットワーク、PIF、スイッチの設定は残します。ネットワークの削除、VLAN や MTU の編集、PIF の削除、ボンド、管理ネットワークの移動、ホストの IP 設定はここでは扱いません。既存のネットワークの MTU を変えると、そのインターフェースが切断され、再接続されることがあります。[ホストとプール](/docs/xoa-hl/hosts-pools/)、[トラブルシューティング](/docs/xoa-hl/troubleshooting/)、[ネットワーク接続を診断する](/docs/xoa-hl/troubleshooting/#network-connectivity)も参照してください。
