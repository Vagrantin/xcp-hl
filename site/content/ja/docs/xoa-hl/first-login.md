このガイドを終えると、XOA-HL にログインでき、ホストが接続され、管理画面が希望の言語で表示されます。

{{< callout type="info" >}}
**対象:** イメージ `xoa-image-20261009-5f33c81`（Xen Orchestra 5.113.2）。公開済みのコードに基づく手順で、テスト用アプライアンスでの通しの確認はまだです。古いイメージや今後のアップデートでは異なる場合があります。
{{< /callout >}}

## 始める前に

- [XO Lite から XOA-HL を展開します](/docs/start/#start-deploy-xoa)。イメージのタグとアプライアンスのアドレスを控えます。
- 展開フォームに入力した XO 管理者のログイン名とパスワードを手元に用意します。ホストの管理アドレスと `root` パスワードも必要です。
- 信頼できる管理ネットワーク上のブラウザーを使います。

すべての操作は **ブラウザー** で行います。ホストやアプライアンスのシェルは不要です。

| アドレスまたはアカウント | 用途 |
| --- | --- |
| ホストの管理アドレス | XO Lite と、XOA-HL からのサーバー接続 |
| XOA-HL アプライアンスのアドレス | Xen Orchestra の Web 管理画面 |
| XO 管理者アカウント | Xen Orchestra へのログイン |
| ホストの `root` アカウント | Xen Orchestra にホストの管理を許可する |
| アプライアンスのシステムアカウント `xo` | SSH 接続専用。Web アカウントではありません |

## 1. アプライアンスを開いてログインする

1. `https://<appliance-address>` を開きます。ホストではなく、アプライアンスのアドレスを使います。
2. 自己署名証明書の警告が出たら、自分のアプライアンスのアドレスであることを確認してから許可します。既存の環境で証明書が変わった場合は、先に理由を調べます。
3. 初回起動が終わるまで待ちます。次に、**展開フォームで設定した XO 管理者アカウント** でログインします。ホストの `root` やアプライアンスの SSH アカウントは使いません。

**確認:** Xen Orchestra の管理画面が開きます。ホストを接続するまで、インベントリが空でも正常です。

{{< callout type="warning" >}}
このイメージでは、初回起動で認証情報の設定に失敗すると、Web アカウントが `admin@admin.net`、パスワード `admin` のまま残ることがあります。新しいアプライアンスで自分のアカウントが使えない場合に限り、信頼できるネットワーク上でこの代替アカウントを試してください。ログインできたら、手順 2 ですぐにパスワードを変更します。どちらも使えない場合は試行を繰り返さず、このページ末尾の表を確認してください。
{{< /callout >}}

## 2. 使い続けるパスワードを設定する

1. メニューの **ユーザーアイコン** を選び、**ユーザー**（`/#/user`）を開きます。
2. パスワード欄に現在のパスワードを入力し、新しいパスワードを 2 回入力します。他で使っていないパスワードにします。**OK** を選びます。
3. 新しいパスワードを安全に保管します。ログアウトし、新しいパスワードで再度ログインします。

**確認:** 新しいパスワードでログインできます。変わるのは Web アカウントだけです。ホストの `root` やアプライアンスの SSH のパスワードは変わりません。

## 3. 管理画面の言語を選ぶ

1. **ユーザーアイコン → ユーザー → 言語設定** を開きます。
2. **日本語** を選びます。表示はすぐに切り替わります。

この設定で変わるのは XOA-HL の管理画面だけです。ドキュメントの言語は、このページ上部のセレクターで別に切り替えます。アプライアンスの一部の項目は、まだ翻訳されていない場合があります。`/#/user` のアドレスでいつでもこの画面を開けます。

## 4. ホストを接続する

1. **設定 → サーバ一覧**（`/#/settings/servers`）を開きます。ホストが既に登録されて接続済みなら、追加し直さずにインベントリを確認します。
2. フォームに、分かりやすいラベル、**ホストの管理 IP アドレスまたはホスト名**、ユーザー名 `root`、インストール時に設定したパスワードを入力します。アプライアンスのアドレスは入力しません。
3. **Connect** を選びます。自己署名証明書の警告が出たら、まず本当に自分のホストか確認します。そのうえで、このサーバーの証明書を許可します。
4. サーバーの行にエラー表示がないか確認します。次にインベントリを開き、プール、ホスト、ストレージリポジトリ（SR）が表示されることを確認します。**Enabled** は接続が有効になっているという意味だけで、接続に成功したことを示すものではありません。

**確認:** ホストとストレージが、接続エラーなしで表示されます。これで[最初の VM を作成](/docs/xoa-hl/create-vm/)できます。

## 5. インストール済みのバージョンを控える

管理者として **XOについて**（`/#/about`）を開きます。**XOA-HL のバージョン** と **XOA-HL VM のバージョン** を控え、イメージのタグと一緒に保管します。VM のバージョンはイメージのビルドを表します。後のパッケージ更新で、アプリケーションのバージョンは変わることがあります。

[リリース一覧](/docs/reference/release-matrix/)には、各リリースに含まれるものが載っています。テスト結果は記録していません。

## うまくいかない場合

| 症状 | 確認すること |
| --- | --- |
| アプライアンスのページが開かない | XO Lite で、アプライアンスの VM が起動しているか確認します。次に、アドレス、ネットワーク、ゲートウェイと、ブラウザーから接続できるかを確認します。動作中の VM に重ねて再展開しないでください。 |
| 展開時の認証情報でログインできない | 初回起動が終わるまで待ち、Web アカウントを使っているか確認します。次に、上記の代替アカウントを試します。アプライアンスのコンソールや SSH を使える場合は、`/var/log/xoa-first-boot.log` を確認します。共有する前に個人情報を取り除いてください。 |
| ホストへのログインに失敗する | ホストのアドレスと `root` パスワードを確認します。Web 管理者のパスワードとは別のものです。 |
| サーバーに証明書エラーが出る | 自己署名証明書を許可する前に、ホストの身元を確認します。説明のつかない変更は許可しないでください。 |
| サーバーは有効だがインベントリが空 | 接続エラーを読みます。アプライアンスからホストに接続できるか、ホストのアドレスが正しいかを確認します。ブラウザーからホストに接続できても、アプライアンスから接続できるとは限りません。 |
