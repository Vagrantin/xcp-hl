このガイドでは、XOA-HL にログインできるアカウントを用意し、ホストを接続して、希望する表示言語を設定します。

{{< callout type="info" >}}
プレビュー用の手順です。イメージ `xoa-image-20261009-5f33c81` と XO 5.113.2 のソースで確認しました。検証用アプライアンスでの一連の操作は未実施です。古いイメージや後のパッケージ更新では動作が異なる場合があります。この翻訳はレビュー待ちの草案です。
{{< /callout >}}

## 始める前に

- [XO Lite から XOA-HL を展開します](/docs/start/#start-deploy-xoa)。イメージのタグとアプライアンスのアドレスを記録してください。
- 展開フォームに入力した XO 管理者のログイン名とパスワードを用意します。ホストの管理アドレスと `root` パスワードも必要です。
- 信頼できる管理ネットワークからブラウザーを使います。このチュートリアルでは XOA-HL 管理者アカウントを使用します。権限を委譲されたアカウントは対象外です。

以下の操作はすべて **ブラウザー** で行います。ホストやアプライアンスのシェルコマンドは不要です。

| アドレスまたはアカウント | 用途 |
| --- | --- |
| ホストの管理アドレス | XO Lite と XOA-HL のサーバー接続 |
| XOA-HL アプライアンスのアドレス | Xen Orchestra の Web 管理画面 |
| XO 管理者アカウント | Xen Orchestra へのログイン |
| ホストの `root` アカウント | Xen Orchestra にハイパーバイザーの管理を許可する |
| アプライアンスのシステムアカウント `xo` | SSH 接続用。Web アカウントとは別 |

## 1. アプライアンスを開いてログインする

1. `https://<appliance-address>` のプレースホルダーを展開時に割り当てたアドレスに置き換えて開きます。ホストではなくアプライアンスのアドレスを使ってください。
2. 自己署名証明書の警告が出たら、自分のアプライアンスのアドレスであることを確認してから許可します。既存環境で証明書が変わった場合は、理由を調べてください。
3. 初回起動の設定が完了するまで待ち、**展開フォームに入力した XO 管理者の認証情報** でログインします。ホストの `root` やアプライアンスの SSH アカウントは使いません。

**確認：** ログイン画面が Xen Orchestra の管理画面に切り替わります。ホストを接続するまでは、インベントリが空でも正常です。

{{< callout type="warning" >}}
このイメージでは、認証情報の初期設定に失敗すると、初期 Web アカウント `admin@admin.net` とパスワード `admin` が残る場合があります。新規アプライアンスで設定したアカウントが使えない場合に限り、信頼できる管理ネットワークでこの代替アカウントを試してください。ログインできたら、次の手順で直ちにパスワードを変更します。どちらも使えない場合は試行を繰り返さず、下の初回起動に関する対処を確認してください。
{{< /callout >}}

## 2. 使用するパスワードを設定する

1. ナビゲーションの **ユーザーアイコン** を選び、**ユーザー**（`/#/user`）を開きます。
2. パスワード欄に現在のパスワード、新しい固有のパスワード、確認用のパスワードを入力し、**OK** を選びます。
3. 新しいパスワードを保存し、ログアウトします。同じ Web ログイン名と新しいパスワードで、再度ログインできることを確認します。

**確認：** 新しいログインに成功します。変更されるのは Web アカウントのパスワードです。ホストの `root` やアプライアンスの SSH パスワードは変わりません。

## 3. 管理画面の言語を選ぶ

1. **ユーザーアイコン → ユーザー → 言語設定** を開きます。
2. **English**、**Français**、**日本語** のいずれかを選び、画面の表示が切り替わることを確認します。

ドキュメントの言語セレクターは、このサイトに対する別の設定です。一方を変更しても、もう一方は変わりません。アプライアンスの一部の項目は英語で表示される場合があります。どの言語でも `/#/user` は同じ画面を示します。

## 4. ホストを接続する

1. **設定 → サーバ一覧**（`/#/settings/servers`）を開きます。目的のサーバーが既に登録され、接続できていれば、重複して追加せずインベントリを確認します。
2. 接続フォームに分かりやすいラベル、**ホストの管理 IP アドレスまたはホスト名**、ユーザー名 `root`、ホストのインストール時に設定したパスワードを入力します。アプライアンスのアドレスは入力しません。
3. **Connect** を選びます。自己署名証明書のエラーが出た場合は、まずホストの身元を確認し、必要に応じてそのサーバーの証明書例外を許可します。
4. 接続行にエラー表示がないか確認します。インベントリを開き、目的のプール、ホスト、SR が表示されることを確認します。**Enabled** は接続設定が有効という意味であり、接続成功の証明ではありません。

**確認：** 目的のホストとストレージが、接続エラーなしで表示されます。[最初の VM を作成する](/docs/xoa-hl/create-vm/)準備ができました。

## 5. インストール済みバージョンを記録する

管理者として **XOについて**（`/#/about`）を開き、**XOA-HL のバージョン** と **XOA-HL VM のバージョン** を記録します。展開したイメージのタグと一緒に保存してください。VM バージョンはイメージのビルドを表します。その後のパッケージ更新でアプリケーションのバージョンが変わる場合があります。

[リリース一覧](/docs/reference/release-matrix/)には記録されたリリースが掲載されています。配布されたコンポーネントを示すものであり、アプライアンスの実機テスト結果ではありません。

## うまくいかない場合

| 症状 | 確認と次の操作 |
| --- | --- |
| アプライアンスのページが開かない | XO Lite でアプライアンス VM の起動を確認し、割り当てられたアドレス、ネットワーク、ゲートウェイ、ブラウザーからの接続を確認します。動作中の VM に重ねて再展開しないでください。 |
| 展開時の認証情報でログインできない | 初回起動を待ち、Web 用の認証情報か確認してから、上記の代替アカウントを確認します。アプライアンスのコンソールや許可された SSH アカウントを使える場合は `/var/log/xoa-first-boot.log` を調べます。共有前に非公開情報を取り除いてください。 |
| ホストの認証に失敗する | ホストのアドレスと `root` パスワードを確認します。Web 管理者のパスワードとは異なります。 |
| サーバーに証明書エラーが出る | 自己署名証明書を許可する前に、ホストの身元を確認します。理由の分からない変更は許可しないでください。 |
| サーバーは有効だがインベントリが空 | 接続エラーを読み、アプライアンスからホストへの通信とホストの管理アドレスを確認します。ブラウザーから接続できても、アプライアンスからの接続を確認したことにはなりません。 |
