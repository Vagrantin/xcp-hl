最初の練習では、本番データを含まない使い捨ての VM を使用します。管理者として **XOA-HL アプライアンス**にログインし、VM、ホスト、ストレージが利用できることを確認してください。重要な VM を変更する前に、独立した[バックアップと復元テスト](/docs/xoa-hl/backup-restore/)を用意します。

## 1. 起動、停止、再起動

対象 VM を開きます (`/#/vms/<id>/general`)。停止中なら **Start** を選び、状態とコンソールでゲストの起動を確認します。実行中の **Stop** と **Reboot** は、最初にゲストの正常なシャットダウンまたは再起動を要求します。

ゲスト側の機能が不足している場合や操作がブロックされている場合、XO は強制操作またはブロックの回避を確認することがあります。続行する前にメッセージを読んでください。強制停止や強制再起動ではゲストのデータを失う可能性があります。可能ならゲスト内でシャットダウンします。タスク実行中に繰り返しクリックしないでください。完了後に VM の状態とコンソールを確認します。成功通知だけではアプリケーションの正常動作を確認できません。

## 2. 保護方法を選ぶ

| 種類 | 目的と制限 |
| --- | --- |
| スナップショット | VM のある時点の状態。元のストレージに依存し、独立したバックアップではない |
| 高速クローン | ストレージ効率のよいコピーを使う別の VM。同じストレージの喪失には備えられない |
| バックアップ | 別に保存する復旧用コピー。隔離した復元で確認する |

VM の変更に伴い、スナップショットとクローンもストレージを消費します。SR の空き容量を確認し、削除するのは確実に識別したテスト用オブジェクトだけにしてください。稼働中のスナップショットはアプリケーションの整合性を保証しません。

## 3. 停止中のスナップショットを作成する

1. 使い捨てのゲストをシャットダウンし、停止状態を確認します。VM の識別情報、ディスク一覧、後で比較する重要でないファイルや設定を記録します。
2. **Snapshots** (`/#/vms/<id>/snapshots`) を開き、**New snapshot** を選びます。この練習ではメモリの保存を選びません。
3. 完了を待ち、日時で新しい行を特定して、分かりやすいテスト名に変更します。タスクのエラーと空き容量を確認します。

作成に失敗したら、エラーを保存し、容量と接続を確認してから再試行します。通知がないだけで、スナップショットが作成されなかったと判断しないでください。

## 4. テスト VM をスナップショットに戻す

重要でないテストデータを変更し、ゲストを再び停止します。記録したスナップショットの **Revert VM to this snapshot** を選びます。この操作は VM の現在の状態を置き換えます。確認画面には現在の状態を先にスナップショットとして保存する選択肢があり、このリリースでは初期状態で有効です。選択と空き容量を確認してください。

実行中に取得したスナップショットに戻すと、XO が VM を起動または再開する場合があります。ここでは停止中に取得したものを使い、手動で起動する前に結果の電源状態を確認します。必要に応じてゲストを起動し、記録したファイルや設定、ディスク一覧を確認します。アプライアンスや本番 VM では練習しないでください。

## 5. 隔離した高速クローンを準備する

停止中の使い捨て VM で **Fast clone** を選びます。新しい VM（初期名の末尾は `_clone`）を探し、異なる識別情報を記録して名前を変更します。[継承したネットワークインターフェースをすべて削除する](/docs/xoa-hl/storage-networks/)か、外部の隔離を確認するまでは停止状態を保ちます。MAC アドレスの自動生成だけでは、コピーされた IP アドレス、資格情報、アプリケーションの識別情報は変わりません。

その後クローンを起動してコンソールを確認します。重複した識別情報を解消し、隔離を確認してからネットワークを再接続してください。エラー後にクローンが見つからなければ、再試行前に一覧とタスクを確認します。この練習ではライブマイグレーション、メモリを含むスナップショット、SR 喪失後の復旧を検証しません。
