ホストやアプライアンスに手を加えずに、XOA-hl から専用 VM で Docker コンテナーを実行します。
{class="lead"}

{{< callout type="warning" >}}
**未リリースです。** このガイドは開発中の機能を説明しています。公開済みの XOA-hl イメージには含まれていません。状況は [Issue #7](https://github.com/Vagrantin/xcp-hl/issues/7) を確認してください。
{{< /callout >}}

## できること {#what-you-get}

XOA-hl に管理者向けの **Containers** ページが追加されます。コンテナーは **Docker VM** で動きます。Docker VM は、用意されたテンプレートから作成する通常の VM で、Docker だけを実行します。

- XCP-hl ホストと XOA-hl アプライアンス自体が Docker を実行することはありません。
- Docker VM は、ほかの VM と同じようにバックアップ、スナップショット、起動、停止ができます。
- 各コンテナーには CPU とメモリーの上限があるため、1 つのアプリケーションがほかのアプリケーションのリソースを奪うことはありません。

## 始める前に {#before-you-begin}

- 管理者として XOA-hl にサインインします。
- Docker VM テンプレートをプールにインポートし、タグ `xcp-hl-docker-template-v1` を付けます。テンプレートが見つからない場合は、Containers ページに案内が表示されます。
- XOA-hl から到達できる、DHCP のあるネットワークを使います。イメージをダウンロードするには、Docker VM からインターネットまたはネットワーク内のレジストリーに接続できる必要があります。

## Docker VM をデプロイする {#deploy-a-docker-vm}

1. **Containers** を開きます。Docker VM がまだない場合は、短い案内と **Deploy Docker VM** フォームが表示されます。
2. 名前、vCPU 数、メモリーを入力します。テンプレート、既定のストレージ、ネットワークがそれぞれ 1 つの場合は、ページが自動的に選択します。
3. **Deploy Docker VM** を 1 回だけ選択します。専用の 32 GiB ディスクを持つ VM が作成され、起動します。
4. 初回起動には数分かかります。VM の準備ができるまでページにその旨が表示されます。2 台目の VM はデプロイしないでください。

## コンテナーを実行する {#run-a-container}

1. **Create container** で、名前とイメージ (例: `nginx:alpine`) を入力します。
2. 上限はそのまま使うか、変更します。既定値は 1 CPU と 256 MiB です。
3. **Create container** を選択します。VM にまだないイメージは先にダウンロードされ、その後コンテナーが自動的に起動します。ダウンロードは、完了するまで一覧の上に表示されます。
4. 各コンテナーで **Start**、**Stop**、**Restart**、**Logs**、**Remove** を使います。削除できるのは停止中のコンテナーだけで、ボリュームは残ります。

**Advanced options** には、1 行に 1 項目ずつ入力します。

| 項目 | 形式 | 例 |
|---|---|---|
| 公開ポート | `HOST:CONTAINER/tcp` | `8080:80/tcp` |
| 永続ボリューム | `NAME:/path` | `web:/usr/share/nginx/html` |
| 環境変数 | `KEY=value` | `TZ=UTC` |

公開したポートには、ページに表示される Docker VM のアドレスで接続できます。環境変数にパスワードを入れないでください。ほかの管理者やログから見える場合があります。

## ダッシュボードで使用状況を確認する {#dashboard}

Docker VM が 1 台でもあると、**Dashboard** に管理者向けの **Docker containers** カードが表示されます。Docker VM ごとに、実行中のコンテナー数と総数、負荷、使用中のメモリーとディスク、実行中のコンテナーが予約している上限が表示されます。

カードは注意が必要な点を強調します。停止中または応答しない Docker VM、失敗したダウンロード、ほぼいっぱいのメモリーやディスク、VM のサイズを超える予約済みの上限です。

## 上限とリソース {#limits}

上限は 1 つのコンテナーの天井であり、予約ではありません。上限の合計が VM を超えることがあり、その場合はページに警告が表示されます。上限を下げるか、Docker VM の VM ページで vCPU またはメモリーを増やしてください。

ディスク容量は、Docker VM のすべてのイメージ、コンテナー、ボリュームで共有されます。空き容量を増やすには、**Images** で使っていないイメージを削除します。

## バックアップと復旧 {#back-up-and-recover}

- Docker VM は、通常の XOA-hl バックアップジョブでバックアップします。イメージ、コンテナー、ボリュームが含まれます。
- XOA-hl アプライアンスもバックアップします。各 Docker VM のアクセスキーを保持しており、キーは再作成できません。
- Docker VM を削除すると、そのキーがページの **Unused access keys** に表示されます。VM が本当になくなった場合にだけ削除してください。プールが切断されていると、その Docker VM は削除されたように見えます。
- XOA-hl を更新しても Docker VM は更新されません。Docker VM のシステムと Docker は別に保守します。

## このバージョンに含まれないもの {#not-in-this-version}

Compose ファイル、コンテナー内のターミナル、特権コンテナー、VM からの共有フォルダー、レジストリーのパスワード保存には対応していません。

最初のバージョンを小さく予測しやすいものにするための選択です。
